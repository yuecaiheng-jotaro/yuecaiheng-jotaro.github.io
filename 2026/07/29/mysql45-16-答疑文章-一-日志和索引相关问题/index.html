学习目标

  • 这一讲要解决的不是“记住 答疑文章（一）：日志和索引相关问题 的答案”，而是训练一种数据库问题拆解方式：先确定 SQL 进入了哪条执行路径，再看优化器、索引、事务、锁或日志系统中哪一段造成了现象。
  • 读完后应该能把一个线上问题拆成四层：现象是什么，证据在哪里，内部机制如何解释，修复动作会不会引入新的风险。
  • 复习时建议把课程案例改写成自己的实验表：SQL、表结构、数据量、索引、事务隔离级别、执行计划、实际耗时和结论。

这一讲可以按一条主线复习：先抓住作者提出的问题，再看正文如何把问题拆成机制，最后把机制落到工程里的观测和动作。我的复习抓手是：

  • 观察入口：执行计划、扫描行数、索引选择、事务状态、锁等待、日志刷盘和主备复制指标。
  • 机制还原：把 SQL 现象还原到 Server 层、优化器、InnoDB、日志系统和复制链路。
  • 行动顺序：先拿证据，再判断根因，最后选择改 SQL、改索引、拆事务、调参数、切主备或补恢复方案。
  • 主要风险：误把现象当根因，或者在没有观测证据时直接改参数、加索引、重启实例。

  • 讲什么：这一节通常围绕 redo log、binlog 或 undo log 展开。复习时要关注它们分别解决崩溃恢复、复制、回滚和一致性中的哪一个问题。
  • 涉及概念：MySQL、事务、redo log、binlog、两阶段提交、主备。
  • 怎么理解：理解这一节时，不要只记结论，要问清楚它发生在 SQL 执行链路的哪一段，以及会不会影响 执行计划、扫描行数、索引选择、事务状态、锁等待、日志刷盘和主备复制指标。
  • 实践动作：落地时建议构造一条最小 SQL：先看 EXPLAIN，再结合事务/锁/日志状态验证课程中的判断。
  • 容易踩坑：常见误区是把一次执行结果当成稳定规律，而忽略数据分布、统计信息、隔离级别和并发状态。

实战清单

  • 遇到慢 SQL 时，先看访问路径、扫描行数、回表次数、排序/临时表，再决定是否改索引或改写 SQL。
  • 并发问题要同时看事务隔离级别、当前读/快照读、锁范围和等待关系，避免只凭现象判断。
  • 高可用和数据安全问题要串起 redo log、binlog、刷盘策略、复制位点和主备切换时序。
  • 把每讲结论落到线上排查入口：EXPLAIN、慢日志、show processlist、show engine innodb status 或 performance_schema。

易错点

  • 只背结论，不复现 SQL 和表结构，导致换一个数据分布就不会判断。
  • 看到慢就加索引，忽略优化器统计信息、回表成本、排序、锁等待和主备延迟。
  • 把止血动作当成长期方案，例如靠重启、强制索引或参数硬调掩盖根因。
