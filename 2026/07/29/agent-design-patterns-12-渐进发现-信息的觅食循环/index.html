学习目标

  • 这一讲的重点是把 渐进发现：信息的觅食循环 从概念名词变成可落地的 Agent 工程模式：它解决哪类失败，依赖哪些状态，怎样观测，如何恢复。
  • 读完后要能回答：这个模式位于感知、记忆、推理、行动还是协作层；它改变的是信息流、控制流、工具边界，还是评估闭环。
  • 复习时可以把每个模式写成一张工程卡片：适用场景、输入输出、关键状态、失败样例、观测指标和上线风险。

这一讲可以按一条主线复习：先抓住作者提出的问题，再看正文如何把问题拆成机制，最后把机制落到工程里的观测和动作。我的复习抓手是：

  • 观察入口：输入摘要、上下文来源、工具调用、模型判断、记忆命中、失败类型、成本和耗时。
  • 机制还原：把 Agent 行为拆成感知、记忆、推理、行动、协作和治理几个可调试模块。
  • 行动顺序：先界定失败模式，再设计状态、工具准入、恢复点和评估集。
  • 主要风险：只调 Prompt，不沉淀状态、证据链、工具边界和评估闭环。

  • 讲什么：这一节属于 Agent 的输入治理：哪些信息该进上下文、哪些要压缩、哪些要延迟发现，直接决定后续推理是否可靠。
  • 涉及概念：索引、Agent、Router、Skill、上下文、工具、感知。
  • 怎么理解：理解这一节时，要把它放回 Agent 生命周期：输入如何进入、状态如何保存、判断如何产生、工具如何执行。
  • 实践动作：落地时先定义输入输出和失败类型，再补观测字段；没有可观测性，模式上线后很难复盘。

实战清单

  • 把模式落地前先写清失败现象：是感知拿错信息、记忆缺证据、推理路线不稳，还是工具执行失控。
  • 每个 Agent 模式都要配观测字段，例如输入摘要、工具调用、置信度、失败类型、成本和耗时。
  • 长任务要把计划、进度、证据和恢复点结构化，避免上下文增长后系统失去可解释性。
  • 把一次失败沉淀成 Skill、规则、检索样例或评估集，形成可复用的系统资产。
  • 机器学习任务要把特征处理、训练、评估和预测封装成可复用 Pipeline，避免训练和线上口径漂移。

易错点

  • 把模式当 Prompt 技巧，而不是输入、状态、工具、评估共同组成的系统设计。
  • 没有记录失败样例和观测字段，上线后只能凭感觉判断 Agent 为什么跑偏。
  • 过早引入复杂编排，却没有明确每个 Agent、工具和记忆层的职责边界。

项目表达

项目里可以这样表达：我会把 渐进发现：信息的觅食循环 落成一个可观测的 Agent 模式，明确输入输出、状态字段、工具边界、失败恢复和评估指标，而不是只改 Prompt。

复习问题

  • 这个模式解决的是感知、记忆、推理、行动，还是多 Agent 编排问题？
  • 要让这个模式上线，需要记录哪些状态、证据、工具调用和失败类型？
  • 如果模型判断错了，系统如何发现、停止、回滚或请求人工介入？
