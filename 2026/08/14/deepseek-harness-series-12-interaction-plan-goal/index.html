模块定位

Agent 产品不是只有模型和工具，还需要用户控制：审批、权限 preset、计划模式、目标管理、反馈、提问。这些能力集中在：

  • packages/interaction/*
  • packages/plan/*
  • packages/goal/*
  • packages/feedback/*
  • packages/context/*

Interaction

Interaction family 包含：

  • commands：人类命令注册与 dispatch。
  • permission-presets：默认权限和当前 session 权限切换。
  • user-approval：工具执行审批。
  • user-questions：agent 请求用户输入。
  • tool-ask-user：模型可见提问工具。

这些能力共同构成“用户在 loop 外控制 agent”的平面。

Permission Presets

权限 preset 影响工具策略和 sandbox。典型模式包括 read-only、workspace-write、更高权限等。权限不是 UI 文案，它会影响 tools/pre-execute、approval service、sandbox policy、fs-sandbox。

Approval

user-approval 提供 ask/approve/reject 语义。工具 runtime 中的 ask decision 会调用 approval service；如果部署没有 approval service，会 degrade 为 deny。

这使 headless、Web、自动化环境可以有不同协作体验，但工具 pipeline 不需要知道 UI 怎么问用户。

Plan Mode

Plan mode 是协作状态，不是普通 prompt 文本。它有直接 entry command 和 reviewed exit。Web UI 有 ui-plan 面板展示状态。

Plan mode 的关键价值是让 agent 在复杂任务中先维护计划和状态，而不是直接执行所有动作。退出也要经过明确控制，避免模型单方面绕过协作约束。

Goal

Goal family 管理 same-session objective persistence 和生命周期。它适合“持续追一个目标”的任务，而不是一次问答。

相关能力包括：

  • goal service。
  • command-goal。
  • tool-goal。
  • goal-round-driver。
  • ui-goal。

Goal 会通过 agent lifecycle 延续，而不是变成一个外部 TODO 文本。

Feedback

Feedback family 支持 human feedback。它可以影响 telemetry gating，也能给产品改进和 session 质量评估提供信号。

Context

Context packages 给模型注入当前请求相关信息：

  • agent instructions。
  • time context。
  • tmux context。
  • session reference。

这些信息必须通过 system prompt/runtime context 或 session events 进入可重建路径。

常见坑

第一，approval 不存在时 ask 会退化为 deny，不是默认 allow。

第二，权限 UI 状态必须和 sandbox/tool policy 对齐。

第三，Plan/Goal 不是普通聊天消息；它们有自己的状态和生命周期。

第四，向模型注入 context 时要考虑是否需要 durable event。
